  ---
  主要な設計ポイント

  CRD (TCInjector)

  spec:
    rules:
      - selector:
          matchLabels:
            app: backend
        minDelay: 10   # ms
        maxDelay: 50   # ms
  クラスタースコープのリソース。複数のルールを持ち、それぞれ独立したラベルセレクタと遅延範囲を設定できます。

  veth 特定の流れ (pkg/veth/finder.go)

  1. Pod の status.containerStatuses[].containerID から container ID を取得
  2. CRI gRPC API (/run/containerd/containerd.sock) で ContainerStatus を呼び出し、PID を取得
  3. /proc/<pid>/ns/net (ホストの /proc をマウント) をネットワーク名前空間パスとして使用
  4. netlink で Pod 名前空間内の veth の peer index を取得
  5. ホスト名前空間でその index に対応するインタフェース名を逆引き

  OVN-Kubernetes では Pod の eth0 は veth ペアになっており、ホスト側が tc 対象になります。

  tc 適用 (pkg/tc/tc.go)

  tc qdisc replace dev <veth> root handle 1: netem delay <N>ms
  - replace で冪等に適用（既存ルールを上書き）
  - remove で後片付け（Pod 削除時・ルール変更時）
  - インタフェース名のバリデーションでシェルインジェクションを防止

  Reconcile の動作

  - TCInjector と Pod の両方を Watch
  - 自ノード (NODE_NAME) 上のマッチする Pod にのみ適用
  - 30秒ごとに再実行してランダム遅延を更新（min〜max の範囲で変化し続ける）
  - Pod 削除・セレクタ変更時は tc ルールを自動削除

  ---

  config/deploy/ に追加するYAMLです：

  # config/deploy/scc.yaml
  apiVersion: security.openshift.io/v1
  kind: SecurityContextConstraints
  metadata:
    name: tc-injector
  # tc(8) と setns(2) のために特権コンテナが必要
  allowPrivilegedContainer: true
  # /proc/<pid>/ns/net にアクセスするためにホスト PID 名前空間が必要
  allowHostPID: true
  allowHostDirVolumePlugin: true
  allowHostIPC: false
  allowHostNetwork: false
  allowHostPorts: false
  # tc/netem および netlink 操作に必要
  allowedCapabilities:
    - NET_ADMIN
    - SYS_ADMIN
  defaultAddCapabilities: []
  requiredDropCapabilities: []
  # root として動作する必要がある（setns は UID 0 または CAP_SYS_ADMIN が必要）
  runAsUser:
    type: RunAsAny
  seLinuxContext:
    type: RunAsAny
  fsGroup:
    type: RunAsAny
  supplementalGroups:
    type: RunAsAny
  volumes:
    - hostPath
    - secret
    - configMap
    - emptyDir
    - projected
    - downwardAPI
  users: []
  groups: []

  # config/deploy/scc-binding.yaml
  apiVersion: rbac.authorization.k8s.io/v1
  kind: ClusterRole
  metadata:

        4 +tc-injector is a Kubernetes operator that injects network latency into pods using the Linux `tc` (traffic control) command. It is designed for chaos engineering,

        6 +## How It Works
        7 +
        8 +tc-injector runs as a **DaemonSet** — one pod per node — and watches for `TCInjector` custom resources. Each `TCInjector` resource defines a list of rules, each p

        9 +
       10 +When a matching pod becomes ready on the node, tc-injector:
       11 +
       12 +1. Connects to the node's CRI socket (containerd or CRI-O) to look up the container's PID.
       13 +2. Enters the container's network namespace via `/proc/<pid>/ns/net`.
       14 +3. Identifies the host-side `veth` interface that backs the container's `eth0`.
       15 +4. Applies a `tc netem` qdisc to that veth interface, injecting the specified delay on all outbound traffic from the pod.
       16 +
       17 +When the pod is deleted or no longer matches any rule, the qdisc is removed and normal scheduling is restored.
